Frequently asked questions

Short answers, each drawn from the README and the docs. For anything not covered here, see the usage guide.

Which databases does locksql support?

MariaDB 10.1+, MySQL 8.0+, PostgreSQL 13+ and SQLite 3. All engines are pure Go. See supported engines.

Which operating systems?

Linux and macOS only, on amd64 and arm64.

Which AI agents does it work with?

Claude Code, Codex, Gemini CLI and Cursor are wired automatically by bare locksql. An agent talks to the console either through the MCP server (locksql mcp, over stdio) or through the locksql CLI from a shell.

Does the agent ever see my database password?

No. The agent never sees a credential and never opens a connection. Credentials are typed at console start (no echo) or read from the OS keychain, and never appear in argv, environment, files, logs, the socket protocol or error messages. No config file may hold a secret.

Can the agent approve its own queries, or turn approval off?

Approval comes only from the console terminal: no socket method approves, and no socket method loosens the policy. --skip-permissions is a console flag only; no client or config file can turn it on, and it is ignored on production profiles. The agent’s account must be separate from the console’s.

Why does the console need its own OS account?

An agent in the console’s own account could read or type into its terminal. Separation is mandatory: without it the console refuses to start. sudo locksql install sets it up.

What happens if I don’t answer the approval prompt?

No answer within 5 minutes means denied. Anything other than y (or the profile name on a production profile) denies the query.

Can locksql run writes or DDL?

Tiers are read < write < ddl < admin; the default is read, which is also enforced server side. Above tier read the human’s approval is the gate, and the server does not restrict what an approved write does within the account’s privileges.

How is personal data protected?

Every output column is traced to its source columns and masked on that source, not on its label; value detectors mask the other cells. Modes are redact (the default), partial and email. Quasi-identifiers (birth date, postal code, gender) are never masked unless you accept them one by one. Masking is best effort: use a database account that cannot read what the agent must never see. More on masking.

Does k-anonymity stop all inference?

No. It is a query-set-size control: it refuses a single query whose PII filter covers fewer than k rows; it does not stop differencing attacks that combine several approved queries. See the example.

Is the connection to the database encrypted?

TLS is not configurable yet. PostgreSQL, MariaDB and MySQL connect like sslmode=prefer: encrypted when the server offers TLS, plain otherwise, and the certificate is not verified, so an active attacker on the path can intercept or downgrade the connection, password included. Use an SSH tunnel (ssh -L) or a Unix socket for remote servers. Full details.

Can text stored in the database manipulate my agent?

It can: locksql assumes the agent may be steered by data, so it treats the agent, and anything that can steer it, such as text stored in the database, as not trusted. Every check runs in the console and every statement needs your approval. Rows are framed as untrusted data in every output, and control and bidirectional characters are escaped so data cannot spoof the approval prompt.

Can the agent change the policy?

Agents may add mask rules and request changes. A change that loosens the policy only takes effect after you confirm it in the console. How policy changes work.

What is logged?

Every login, policy change, refusal, decision, catalog read and logout, in a JSONL audit log (mode 0600). Records contain the SQL and metadata, never secrets and never row data.

What is --skip-permissions for?

Fast local iteration: it auto-approves statements that the tier and the weight check allow. It is ignored on production profiles, never auto-approves an unmasked query, never overrides a REFUSE verdict, and each auto-approval is audited.

Can several people share one console, or export data?

No: one console per profile and project, one request at a time, no remote or shared consoles, no data export.

Do I need Go to install it?

No. Releases ship static binaries and Linux packages; no Go toolchain is needed. Building from source needs Go 1.26 or later. Install options.

Is locksql stable?

It is a pre-release (v0.1.x).

How do I report a vulnerability?

Privately, through GitHub security advisories, not in a public issue. See SECURITY.md.
